- 작성일: 2026-11-10
- 상위 문서: [개발계획서](개발계획서.md) Phase 8 (지형·등고선·경사도)
- 목적: 서버가 없는 우리 사이트(GitHub Pages)에서 **정확한 지형(표고·등고선·경사도·경사방향)** 을 쓰기 위해, 국토지리정보원 연속수치지형도의 등고선·표고점을 **미리 10m 격자로 가공해 타일로 올려 두는** 절차를 정한다. 처음에는 손으로 몇 단계를 거치지만, **나중에 명령 하나로 다시 만들 수 있게(자동화)** 처음부터 스크립트로 짠다.

## 3. 결과물 (앱이 읽는 형태)

### 3.1 지형 격자 타일
- **격자**: EPSG:5179 기준 **10m** 간격 (sitedia와 같은 수준. 1:5,000 등고선 5m 간격에 맞는 해상도)
- **타일**: 256 × 256칸 = **2,560m × 2,560m**. 이름 `dem/{열}_{행}.png` — 열·행은 EPSG:5179 좌표를 2,560으로 나눈 정수
- **값**: 표고(m) × 10 + 10,000 을 16비트로 저장 (−1,000.0 ~ 5,553.5m, 0.1m 단위). 자료 없음 = 0
- **인코딩**: PNG RGB 8비트 — R = 상위 8비트, G = 하위 8비트, B = 자료 유무 플래그(255 있음 / 0 없음)
  - 브라우저 캔버스는 16비트 PNG를 8비트로 깎아 버리므로 8비트 두 채널에 나눠 담는다
  - 매끈한 지형은 PNG의 행 필터로 잘 압축된다. **T2 단계에서 PNG와 `행별 차분 + gzip(.bin.gz)`를 실제 타일로 비교해 작은 쪽으로 확정**
- **대체**: 자료가 없는 칸(바다, 다른 시도)은 앱에서 Terrarium 타일 값으로 채우고 "대체 자료" 표시

### 3.2 목록 파일 `dem/manifest.json`
```json
{
  "version": "2026.1",
  "source": { "name": "국토지리정보원 연속수치지형도 등고선·표고점", "license": "CC BY", "updated": "2026-10-01", "files": ["등고선_0NN.zip", "..."] },
  "builtAt": "2026-11-??",
  "crs": "EPSG:5179", "cell": 10, "tile": 256, "encoding": "png-rg16-offset10000-scale10",
  "regions": ["광주", "전남", "전북"],
  "tiles": ["{열}_{행}", "..."],
  "checks": [{ "name": "무등산 천왕봉", "official": 1187, "built": 1186.2 }]
}
```

### 3.3 등고선 선
- 따로 저장하지 않는다. 앱이 격자에서 **그때그때 등고선을 뽑는다**(d3-contour, 마칭 스퀘어). 간격은 반경 안 기복에 따라 1·2·5·10m 자동
- 이유: 저장 용량을 절반 이하로 줄이고, 등고선·경사도·단면이 모두 같은 격자에서 나와 서로 어긋나지 않음

## 4. 저장 위치와 용량

- **별도 저장소 `CJG10040/site-agent-terrain`** + GitHub Pages → 주소 `https://cjg10040.github.io/site-agent-terrain/dem/...`
  - 앱(`/site-agent/`)과 **같은 도메인**이라 CORS 문제가 없음
  - 앱 저장소를 무겁게 만들지 않고, 지형만 따로 갱신·배포
- 용량 추정 (T2에서 실측해 고침)
  - 면적: 광주 약 500 + 전남 약 12,300 + 전북 약 8,100 = **약 20,900㎢**
  - 10m 격자 약 2.1억 칸 → 육지가 걸친 타일 약 3,500~4,000장
  - 칸당 0.8~1.2바이트로 보면 **약 170~250MB** → GitHub 권장 한도(저장소 1GB, 파일 100MB) 안
- 전국으로 넓히면(약 10만㎢ → 약 1GB) 한도에 닿으므로, 그때 시도별 저장소로 나누거나 외부 저장소(예: Cloudflare R2)로 옮기는 것을 다시 검토

## 5. 가공 절차 (스크립트)

도구: **Python 3.12** (설치됨) + 가상환경 `tools/terrain/.venv`
패키지(공개 2주 이상 지난 버전으로 고정): `numpy`, `scipy`(삼각망 보간), `pyshp`(SHP 읽기, GDAL 불필요), `pyproj`, `Pillow`, `openpyxl`(파일 목록 xlsx)

| 단계 | 스크립트 | 하는 일 | 확인 |
|---|---|---|---|
| T0 조사 | `inspect.py` | ZIP 목록, SHP 필드·좌표계·개수·높이 범위, 이상값(음수·9999 등) 보고 | 보고서 `reports/inspect.md` |
| T1 색인 | `index.py` | 각 선·점의 경계 상자를 읽어 타일별 목록 작성 (수억 개 정점을 한 번에 메모리에 올리지 않기 위해) | 타일별 선 수 분포 |
| T2 격자화 | `grid.py` | 타일마다 **주변 200m 여유**를 둔 범위의 등고선 정점(10m 간격으로 촘촘히)과 표고점 → 들로네 삼각망 → 10m 격자 보간. 가장 가까운 자료가 400m 넘게 먼 칸은 "자료 없음" | 시험 타일 1장(광주 동구) 눈으로 확인 |
| T3 인코딩 | `encode.py` | PNG / .bin.gz로 저장, 크기 비교 | 타일당 평균 크기 |
| T4 검증 | `verify.py` | ① 기준 산 높이 비교(±5m) ② 타일 경계 이음매(인접 타일 가장자리 차이) ③ 표고점 위치의 값 비교(전체 오차 분포) ④ 미리보기 그림(음영기복도) | `reports/verify.md` + 그림 |
| T5 배포 | `publish.py` | `manifest.json` 작성 → 지형 저장소에 복사 → 커밋·푸시 | Pages 주소에서 타일 1장 받기 |

기준 산 (T4, 공식 높이는 국토지리정보원 고시값으로 다시 확인):
- 무등산 천왕봉(광주·화순·담양) 약 1,187m
- 덕유산 향적봉(전북 무주) 약 1,614m
- 반야봉(지리산, 전북 남원·전남 구례) 약 1,732m
- 노고단(전남 구례) 약 1,507m
- 모악산(전북 김제·완주) 약 794m
- 월출산 천황봉(전남 영암) 약 809m

산꼭대기 값은 꼭대기 반경 150m 안의 가장 높은 칸으로 비교한다(sitedia와 같은 기준).

## 6. 앱에서 쓰는 방법 (Phase 8 개발 범위)

1. 대지 반경의 경계 상자 → EPSG:5179로 바꿔 필요한 타일 계산 → `manifest.json`에 있는 타일만 요청
2. 타일 모자이크 → 반경 안 격자
3. **50m 평활**(가우시안) 후 경사도(Horn 방식)·경사방향(8방위) 계산 — 평활하지 않으면 평지에도 몇 도의 잡음이 생김(sitedia도 같은 이유로 50m 평활)
4. 도판: 지형·등고선(표고 단계 색 + 등고선, 기복 3m 미만이면 등고선 생략) / 경사도(5·10·15·20° 경계) / 경사방향(8방위 × 가파름)
5. 사실 카드: 대지 안 고저차, 대지 평균 경사도, 반경 안 최고·최저점 방향과 거리, 대지가 놓인 비탈 방향
6. 단면 도판(Phase 11)과 3D 지형(Phase 11)도 같은 격자를 씀
7. 자료가 없는 곳은 Terrarium으로 채우고 도판·카드에 "대체 자료(건물 높이가 섞일 수 있음)" 표시
8. 한계 표기: "10m 격자 — 옹벽·계단·작은 둔덕은 나타나지 않음", "표고는 참고값, 측량·인허가 근거 아님"

## 7. 자동화 계획 (나중에)

| 단계 | 내용 | 막히는 점 |
|---|---|---|
| A. 한 명령 실행 | `python tools/terrain/build.py --raw <내려받은 폴더> --regions 광주,전남,전북 --out <지형 저장소>` 가 T0~T5를 차례로 실행, 중간 결과를 남겨 끊겨도 이어서 진행 | 없음 (처음부터 이렇게 만듦) |
| B. 갱신 감지 | 브이월드 다운로드 목록의 "갱신일"을 읽어 `manifest.json`의 원자료 날짜와 비교 → 새 자료가 있으면 알림 | 목록 조회는 로그인 불필요 (확인 필요) |
| C. 받기 | ZIP 다운로드는 로그인이 필요해 **사람이 받음**. 받은 파일을 정해진 폴더에 넣으면 A가 새 파일만 처리 | 브이월드에 로그인 없는 다운로드 API가 있는지 확인 필요 |
| D. 배포 자동화 | 처리 결과를 지형 저장소에 푸시하면 GitHub Actions가 Pages로 배포 | 원자료(수 GB)는 Actions에 올리지 않고 내 PC에서 처리 |
| E. 검증 보고서 | 매 빌드마다 기준 산 오차표·이음매 검사·미리보기 그림을 `reports/`에 자동 생성, 오차가 기준을 넘으면 배포 중단 | 없음 |
| F. 지역 확장 | `--regions`에 시도를 추가하면 같은 절차. 전국은 용량 때문에 저장소 분할 | 저장소 한도 |
